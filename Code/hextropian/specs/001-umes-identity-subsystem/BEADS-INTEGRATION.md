# Beads Integration Guide for UMES

This directory contains scripts to integrate UMES tasks with Beads persistent task memory.

## Overview

The UMES feature has **288 tasks** organized across 11 phases. These scripts automate:

1. **Import** - Bulk create all 288 tasks as Beads issues
2. **Update** - Add Beads IDs to tasks.md for bidirectional tracking
3. **Dependencies** - Create phase-based and test-first blocking dependencies

## Prerequisites

- Beads CLI installed and configured
- tasks.md generated by `/speckit.tasks`
- Beads repository initialized (`.beads/` directory exists)

## Quick Start

```bash
# Navigate to feature directory
cd /Users/speed/code/hextropian/specs/001-umes-identity-subsystem

# 1. Dry run to preview
./import-tasks-to-beads.sh --dry-run

# 2. Import all tasks (takes ~5-10 minutes for 288 tasks)
./import-tasks-to-beads.sh

# 3. Update tasks.md with Beads IDs
./update-tasks-with-beads-ids.sh

# 4. Create dependencies
./create-beads-dependencies.sh

# 5. Verify
bd ready              # Show tasks ready to work
bd list --status=blocked  # Show blocked tasks
bd stats              # Project statistics
```

## Scripts

### 1. import-tasks-to-beads.sh

**Purpose**: Bulk create Beads issues from tasks.md

**Usage**:
```bash
./import-tasks-to-beads.sh [--dry-run] [--start TASK_ID] [--end TASK_ID]
```

**Options**:
- `--dry-run`: Print commands without executing
- `--start T050`: Start importing from T050 (useful for resuming)
- `--end T100`: Stop at T100 (useful for partial import)

**Output**:
- Creates 288 Beads issues with appropriate labels and types
- Generates `beads-mapping.txt` with TaskID -> Beads ID mappings
- Rate-limited (pauses every 10 tasks to avoid overwhelming Beads)

**Labels Applied**:
- `umes` - All tasks
- `mvp`, `important`, `nice-to-have` - Based on P1/P2/P3 priority
- `phase-1-setup` through `phase-11-deployment` - Phase grouping
- `test` or `implementation` - Task type
- `cloud-agnostic`, `authentication`, `authorization`, etc. - Story-specific

**Example**:
```bash
# Import first 50 tasks as a test
./import-tasks-to-beads.sh --start T001 --end T050

# Import remaining tasks
./import-tasks-to-beads.sh --start T051
```

### 2. update-tasks-with-beads-ids.sh

**Purpose**: Update tasks.md with Beads issue IDs

**Usage**:
```bash
./update-tasks-with-beads-ids.sh [--dry-run]
```

**Before**:
```markdown
- [ ] [T001] [P1] [SETUP] Initialize project structure...
```

**After**:
```markdown
- [ ] (beads-abc123) [T001] [P1] [SETUP] Initialize project structure...
```

**Features**:
- Creates backup of tasks.md before modification
- Reads beads-mapping.txt generated by import script
- Updates all task checkboxes with Beads IDs
- Skips tasks with failed imports

**Example**:
```bash
# Preview changes
./update-tasks-with-beads-ids.sh --dry-run

# Apply changes
./update-tasks-with-beads-ids.sh
```

### 3. create-beads-dependencies.sh

**Purpose**: Create blocking dependencies between Beads issues

**Usage**:
```bash
./create-beads-dependencies.sh [--dry-run]
```

**Dependencies Created**:

**Phase-Level Blocking**:
```
Phase 1 (Setup) → Phase 2 (Foundation) → Phase 3-9 (User Stories) → Phase 10 (Polish) → Phase 11 (Deployment)

US1 (Cloud deployment) blocks all other user stories (foundational)
US2 (Auth) + US3 (Authz) block US4 (SDK), US5 (API Keys), US7 (Multi-tenant)
```

**Test-First Blocking**:
```
T013 (User model tests) → T014 (User model implementation)
T089 (Login tests) → T090 (Login implementation)
etc.
```

**Critical Path Blocking**:
```
KMS adapters → JWT service
IdP adapters → Auth endpoints
Models → Services
Audit logging → All endpoints
```

**Example**:
```bash
# Preview dependencies
./create-beads-dependencies.sh --dry-run

# Create dependencies
./create-beads-dependencies.sh

# Verify blocking
bd list --status=blocked
```

## Workflow with Beads

### Starting Work

```bash
# Find available work (respects dependencies)
bd ready

# Claim a task
bd show beads-abc123
bd update beads-abc123 --status=in_progress

# Work on the task...

# Mark complete
bd close beads-abc123

# Check off in tasks.md
# - [x] (beads-abc123) [T001] [P1] [SETUP] Initialize project structure...
```

### Tracking Progress

```bash
# View project statistics
bd stats

# List in-progress work
bd list --status=in_progress

# Check what's blocked
bd blocked

# View task details with dependencies
bd show beads-abc123
```

### Adding Discoveries

When you discover new work during implementation:

```bash
# Create new task
bd create --title="Fix edge case in token validation" --type=bug --labels="umes,us2,authentication" --status=todo

# Link to parent task
bd dep beads-parent beads-new-task  # Parent blocks new task
```

### Session Management

At end of session:

```bash
# Sync Beads changes
bd sync --from-main

# Update tasks.md checkboxes
# (Manual for now, or create sync script)

# Commit progress
git add tasks.md .beads/
git commit -m "chore: Update UMES task progress"
```

## Troubleshooting

### Import Failed for Some Tasks

```bash
# Check beads-mapping.txt for FAILED entries
grep FAILED beads-mapping.txt

# Re-import specific range
./import-tasks-to-beads.sh --start T050 --end T060
```

### Duplicate Beads Issues

```bash
# Find duplicates
bd list --labels=umes | grep "\[T001\]"

# Delete duplicates
bd delete beads-duplicate-id
```

## Integration with Spec Kit

Spec Kit workflows remain the primary source of truth:

- **spec.md** - Feature specification (WHAT/WHY)
- **plan.md** - Technical implementation (HOW)
- **tasks.md** - Executable checklist (WHEN/ORDER)
- **Beads** - Persistent task memory (PROGRESS/DISCOVERIES)

**Workflow**:
1. `/speckit.specify` → Creates spec.md
2. `/speckit.plan` → Creates plan.md
3. `/speckit.tasks` → Creates tasks.md
4. `./import-tasks-to-beads.sh` → Syncs to Beads
5. `bd ready` → Drive implementation from Beads
6. Update both tasks.md and Beads as work completes

## Advanced Usage

### Bulk Close Completed Tasks

```bash
# Get list of completed task IDs from tasks.md
grep "^- \[x\]" tasks.md | grep -oE 'beads-[0-9a-f]+' > completed-ids.txt

# Close all in Beads
while read -r beads_id; do
  bd close "$beads_id"
done < completed-ids.txt
```

### Generate Progress Report

```bash
# Count completed tasks per phase
for phase in {1..11}; do
  total=$(bd list --labels="phase-${phase}" --status=open,in_progress,done | wc -l)
  done=$(bd list --labels="phase-${phase}" --status=done | wc -l)
  echo "Phase $phase: $done / $total completed"
done
```

### Create Phase Epics

```bash
# Create epic for each phase
```
